# TorrMovie

Отдельное приложение для рутованного LG webOS: поиск торрентов в VilkaDB → выбор раздачи → выбор видеофайла → просмотр через **локальный или внешний** TorrServer. Управление пультом и Magic Remote, сортировка по сидам/размеру, magnet/HTTP .torrent, список торрентов на сервере, локальная история с продолжением позиции.

## Требования

- Рутованный LG webOS с webOSbrew/Homebrew Channel, SSH, `/usr/bin/node` 8.12+ (проверено на webOS 5.6.0).
- Для локального режима: Linux/webOS на ARMv7, ARM64, x86 или x86_64 и доступ к GitHub для первой установки TorrServer MatriX.147.2. Альтернатива — внешний TorrServer в локальной сети (ранее проверен с MatriX.142.2). Работоспособность локального движка на конкретной модели ТВ требует проверки.
- На компьютере для сборки: Node.js 22+, npm, GNU tar, OpenSSH. Зависимости из npm не требуются.

## Разработка

```sh
TORRSERVER_URL=http://192.168.1.100:8090 npm start
# http://127.0.0.1:32190
npm run check
npm test
npm run build
```

Для постоянных настроек скопируйте `config.example.json` в `config.json` или используйте экран «Настройки». Выберите локальный режим или установите адрес внешнего сервера. `config.json` исключён из Git. Переменные `PORT`, `HOST`, `TW_CONFIG` переопределяют порт/интерфейс/путь конфигурации. На телевизоре помощник слушает только `127.0.0.1:32190`; не открывайте его в интернет.

## Установка на телевизор

```sh
./scripts/install-tv.sh root@TV_IP http://TORRSERVER_IP:8090
```

SSH/SCP спросит пароль телевизора. Скрипт не сохраняет его. Он собирает IPK, копирует его в `/tmp`, вызывает штатный webOS appInstallService, устанавливает автозапуск помощника через webOSbrew и запускает приложение. ID приложения: `org.torrenter.watcher`; название ярлыка: **TorrMovie**.

IPK: `dist/org.torrenter.watcher_0.4.1_all.ipk`. Простая установка IPK через Dev Manager без root-скрипта недостаточна: нужен локальный Node-помощник. Системные разделы прошивки не изменяются. Повторная установка обновляет приложение, сохраняя настройки и историю.

На ТВ:

- приложение: `/media/developer/apps/usr/palm/applications/org.torrenter.watcher/`;
- конфигурация: `/var/lib/torrenter-watcher/config.json` (права 600, каталог 700);
- журнал/ PID помощника: `/var/lib/torrenter-watcher/helper.log`, `helper.pid`;
- автозапуск: `/var/lib/webosbrew/init.d/65-torrenter-watcher`;
- перезапуск: `sh /var/lib/webosbrew/init.d/65-torrenter-watcher restart`.

Для удаления сначала остановите PID помощника (проверьте `cmdline`), удалите его init.d-файл и удалите приложение обычным способом на ТВ. Конфигурацию/историю можно оставить для последующей установки. Root и webOSbrew остаются как были.

## Как пользоваться

1. В настройках выберите «На этом устройстве» и нажмите «Установить и запустить». Дождитесь статуса «Работает» — адрес вручную вводить не нужно. Для внешнего сервера выберите соответствующий режим, укажите адрес и учётные данные, сохраните настройки.
2. По умолчанию поиск идёт через VilkaDB — тот же портал, что в ForkPlayer.
3. Введите название, нажмите «Найти», выберите раздачу. Появятся видеофайлы; откройте нужный.
4. OK — пауза/продолжение, ←/→ — ±30 секунд, клик по полосе — переход в выбранное место, ↓ — открыть горизонтальный список видео в той же папке, ←/→ в этом списке — выбрать серию, OK — переключить с продолжением сохранённой позиции; ↑/BACK — закрыть список, ↑ вне списка — скрыть панель, жёлтая кнопка — смена аудиодорожки (если API плеера её предоставляет), BACK — к списку файлов. Системная громкость остаётся на кнопках громкости.
5. «История» хранит последние 100 открытых видео и позиции на этом ТВ; повторное открытие поднимает запись наверх, самая старая удаляется при превышении лимита; «На сервере» показывает список выбранного TorrServer.

Источники можно переключать: VilkaDB, Rutor, Torznab, Jacred. Rutor включается кнопкой в настройках, его первый индекс загружается несколько минут. Для Torznab настройте индексаторы на стороне TorrServer. Для Jacred нужен доступный адрес агрегатора, при необходимости API-ключ.

## Локальный TorrServer

«Установить и запустить» загружает официальный бинарный файл MatriX.147.2 для архитектуры устройства, проверяет закреплённую SHA-256 и автоматически выбирает локальный режим. Загрузка идёт в фоне, статус и ошибки видны в настройках. Повторное нажатие использует установленный файл. При недоступности GitHub можно повторить установку позже.

HTTP API TorrServer слушает только `127.0.0.1:32191`; соединения с участниками раздач используют сетевые интерфейсы устройства. Для разработки порт можно изменить через `TW_TORRSERVER_PORT`. Настройки внешнего сервера сохраняются отдельно, его логин и пароль локальному процессу не передаются.

Выбранный локальный режим автоматически запускается вместе с Node-помощником при перезагрузке телевизора. Закрытие окна приложения не останавливает сервер. «Остановить» завершает процесс и переключает режим на внешний, отключая локальный автозапуск. Сохранение внешнего режима также останавливает локальный процесс. Остановка помощника завершает дочерний TorrServer.

На ТВ бинарный файл, база и настройки хранятся в `/var/lib/torrenter-watcher/torrserver/`, журнал — `torrserver/torrserver.log` (ротация при запуске после 1 МиБ). При разработке это каталог `torrserver/` рядом с файлом конфигурации. Установка обновления приложения сохраняет эти данные. Для полного удаления после остановки помощника можно удалить этот каталог. Бинарник не входит в IPK: первая установка требует интернета и места для загрузки.

На Linux x86_64 проверены загрузка с SHA-256, запуск настоящего TorrServer, ограничения кэша, остановка и повторный запуск. Проверка потокового просмотра на самом webOS с этой версией ещё нужна; тяжёлые раздачи могут превышать возможности памяти и процессора ТВ.

## Архитектура и ограничения

- `app/`: лёгкий ES5-интерфейс без фреймворка, CDN и сторонних скриптов; нативный `<video>` использует возможности webOS.
- `server/`: локальный Node 8-совместимый HTTP-помощник: поиск, управление локальным TorrServer, CORS/Auth для внешнего сервера, потоковая передача Range-запросов без транскодирования.
- В локальном режиме скачивания и пиры работают на ТВ: кэш видео в памяти 32 МиБ, до 20 соединений, сохранение видео на диск выключено. Расход памяти всего процесса выше размера кэша; GOMEMLIMIT=96MiB — мягкий ориентир Go, а не жёсткий лимит. Внешний режим переносит эту нагрузку на отдельную машину. Помощник передаёт HTTP-поток с противодавлением; его V8 heap ограничен 64 МБ.
- Нет сидов — нет гарантии запуска. Счётчик сидов каталога может отставать от реального состояния. Ошибки и ожидание отображаются, запросы метаданных ограничены по времени.
- Поддержка кодеков зависит от ТВ. TorrServer передаёт оригинальный файл и не исправляет неподдерживаемые звук/видео.
- VilkaDB — внешний HTTP-портал без гарантии стабильности API. HTML/JS/CSS портала не исполняются. Запрос поиска отправляется выбранному источнику, а история остаётся в `localStorage` телевизора.
- Пароль и API-ключ не возвращаются в API чтения настроек и не пишутся в браузерное хранилище. Локальные изменения защищены токеном сессии и проверкой Host. Помощник не предназначен для доступа из интернета.

Исследование протоколов и источники: [docs/research.md](docs/research.md).


## Главная и каталог (0.2.0)

При запуске открывается «Главная»: локальное «Продолжить просмотр», популярное VilkaDB, фильмы и сериалы текущего года. В каждой подборке до 18 карточек; ряды прокручиваются горизонтально пультом и Magic Remote. Карточка показывает постер, рейтинг, год и тип. Нажатие открывает описание и автоматически ищет раздачи выбранным источником. Список появляется под постером и описанием; выбор раздачи ведёт к обычному пути через TorrServer. BACK из списка файлов возвращает к тому же фильму, выбранной раздаче и прокрутке.

Каталог кэшируется на 3 часа, описания — на сутки, нормализованные данные сохраняются рядом с config.json в catalog-cache.json. При временной недоступности источника показывается сохранённая подборка. Постеры идут через локальный помощник; его кэш изображений ограничен 6 МБ. У каталога нет API-ключа. История портала не импортируется — ряд продолжения берётся только из локальной истории этого устройства.

Подборки новых фильмов/сериалов фильтруются по году источника; наличие карточки не гарантирует доступную торрент-раздачу. Источник метаданных — VilkaDB.


## Каталог (0.3.2)

Отдельный пункт меню «Каталог» позволяет просматривать все годы, выбирать фильмы или сериалы, жанр и минимальный рейтинг (любой, от 5/6/7/8/9). Наборы жанров соответствуют выбранному типу; при смене типа жанр сбрасывается. Доступен точный год (1900 — текущий) и сортировки «Популярное», «Новее», «По рейтингу». Источник не поддерживает сортировку всего каталога: сортировки по году и рейтингу применяются к текущей странице; одинаковые значения сохраняют исходный порядок. Нажмите «Показать», чтобы применить фильтры. Страницы содержат до 36 карточек; переходы «Следующая»/«Предыдущая» сохраняют фильтры.

В пульте ↑/↓ меняют значение выбранного поля, ←/→ переходят между полями. OK на «Показать» применяет выбор. Из карточки можно открыть описание и найти раздачи. BACK возвращает к выбранной карточке и той же странице каталога. Результаты фильтрации кэшируются на час в существующем ограниченном кэше метаданных. Минимальный рейтинг дополнительно проверяется после ответа источника.

## Плеер и серии (0.4.1)

Панель плеера и список серий автоматически скрываются после 5 секунд без действий во время воспроизведения. Пауза, буферизация и незавершённая перемотка оставляют панель видимой; после восстановления просмотра таймер запускается снова. Клик по полосе перемотки больше не закрепляет панель, мелкое дрожание указателя игнорируется.

Стрелка ↓ открывает горизонтальный ряд видео из той же папки раздачи, выделяя текущую серию. ←/→ перемещают выбор, OK переключает серию и сохраняет позицию предыдущей. Выбор текущей серии закрывает список. ↑ или BACK закрывают список; следующий BACK выходит из плеера. Для перемотки при открытом списке доступны кнопки перемотки пульта или клик по полосе.

Внизу карточек файлов и серий показана тонкая линия: пустая — файл ещё не смотрели, частично заполненная — позиция просмотра, полная — просмотрено не менее 95% или достигнут конец видео. Прогресс берётся из локальной истории этого ТВ, которая хранит последние 100 файлов.
