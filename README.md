# 🐺 VolKino

Приложение для Android TV, Android-планшетов и рутованного LG webOS: поиск торрентов в VilkaDB → выбор раздачи → выбор видеофайла → просмотр через **локальный или внешний** TorrServer либо Filmix. Управление пультом и Magic Remote, сортировка по сидам/размеру, magnet/HTTP .torrent, список торрентов на сервере, локальная история с продолжением позиции.

## Android TV и планшеты

Один APK устанавливается на **Android TV и планшеты с Android 6.0+** (ARMv7, ARM64, x86_64). На TV есть ярлык Leanback, управление стрелками/OK/BACK и медиакнопками пульта. На смартфонах и планшетах доступны обе ориентации, экранная клавиатура и прокрутка касанием. Android воспроизводит видео встроенным LibVLC 3.6.5 с декодированием звука, выбором аудиодорожек, паузой и перемоткой. «Серии» открывает список файлов текущей папки поверх видео с продолжением выбранного файла из истории. В меню «Звук и изображение» доступны исходные пропорции, заполнение с обрезкой и растяжение на весь экран; выбранный режим сохраняется. Обработка «Автофикс звука» относится к плееру webOS и браузера.

Node.js-помощник и TorrServer MatriX.147.2 встроены в APK. Root, отдельный компьютер и загрузка исполняемых файлов при первом запуске не нужны. На новой установке по умолчанию выбрано «На этом устройстве»: встроенный TorrServer запускается автоматически. Сохранённый выбор внешнего сервера сохраняется; старый конфиг с внешним адресом без поля режима тоже продолжает использовать этот адрес. При падении или зависании локальный процесс перезапускается автоматически с повторными попытками до 30 секунд между неудачными запусками. Интерфейс повторяет проверку соединения каждые 5 секунд. Ручная остановка, выбор внешнего сервера и выход из приложения отключают автоперезапуск. Каталог, поиск и Filmix используют тот же код, что и webOS.

Сборка на Linux/macOS: Node.js 22.12+, npm, JDK 17+, Android SDK Platform 35, Build Tools 35.0.0, NDK 27.2.12479018, CMake 3.22.1, `zip` и `unzip`. Укажите SDK через `ANDROID_HOME` или `android/local.properties` (`sdk.dir=/путь/к/Android/Sdk`). Компоненты SDK можно установить Android Studio либо `sdkmanager`:

```sh
sdkmanager "platforms;android-35" "build-tools;35.0.0" "ndk;27.2.12479018" "cmake;3.22.1" "platform-tools"
npm ci
npm run build:android
adb install -r dist/volkino_0.8.1_android-debug.apk
```

Результат — подписанный отладочным ключом APK для установки вручную. Одна сборка содержит все три архитектуры. Для обновления с сохранением данных используйте тот же ключ подписи (стандартный debug-ключ лежит в `~/.android/debug.keystore`). `npm run build:android:release` создаёт **неподписанный** release APK; перед распространением его нужно подписать своим постоянным ключом через `apksigner`.

Первая сборка скачивает закреплённые бинарники Node.js Mobile v18.20.4 и TorrServer, проверяет SHA-256 из `android/vendor-lock.json` и кеширует их в `android/vendor/`. Gradle Wrapper включён в проект; Android Studio и `./android/gradlew -p android assembleDebug` также пересобирают интерфейс и assets. Моки, пользовательская конфигурация и аккаунты в APK не включаются.

Помощник работает отдельным приватным процессом и слушает loopback. Его порт сохраняется между запусками, чтобы история WebView оставалась доступна. TorrServer выполняется из штатного каталога нативных библиотек APK — Android запрещает запуск скачанных бинарников из каталога данных приложения. Закрытие приложения кнопкой «Назад» останавливает помощник и локальный TorrServer; при сворачивании видео ставится на паузу. Фоновое воспроизведение не реализовано. Настройки и история переживают обновление с той же подписью; удаление приложения очищает их.

Проверено: запуск APK, реальный каталог и локальный TorrServer в эмуляторе Android 15 x86_64; сенсорная навигация и плеер в браузерных тестах 1280×800 и 800×1280. Физические TV/планшеты и доступные на них кодеки требуют проверки. Встроенный Node.js Mobile собран с выравниванием ELF 4 КБ: устройства с размером страницы памяти 16 КБ требуют отдельной пересборки Node.js; эта сборка для них не заявлена. Нужен актуальный Android System WebView. Каталог использует WebView, воспроизведение Android — LibVLC. В эмуляторе Android 15 проверены AAC, AC-3 и E-AC-3: воспроизведение с сохранённой позиции и активный PCM-выход Android с ненулевым сигналом. Исправление звука требует проверки на физических устройствах, включая vivo X300.

Лицензии включены в assets APK: `NODE-LICENSE`, `TORRSERVER-LICENSE`, `LIBVLC-LICENSE`, `THIRD-PARTY-NOTICES.txt`. LibVLC Android 3.6.5 — LGPL-2.1; [исходники и инструкции сборки](https://code.videolan.org/videolan/libvlcjni/-/tree/3.6.5). Node.js Mobile — MIT и лицензии включённых компонентов; TorrServer — GPL-3.0. Точные исходники: [Node.js Mobile v18.20.4](https://github.com/nodejs-mobile/nodejs-mobile/tree/v18.20.4), [TorrServer MatriX.147.2](https://github.com/YouROK/TorrServer/tree/MatriX.147.2).

## Требования

- Рутованный LG webOS с webOSbrew/Homebrew Channel, SSH, `/usr/bin/node` 8.12+ (проверено на webOS 5.6.0).
- Для локального режима: Linux/webOS на ARMv7, ARM64, x86 или x86_64 и доступ к GitHub для первой установки TorrServer MatriX.147.2. Альтернатива — внешний TorrServer в локальной сети (ранее проверен с MatriX.142.2). Работоспособность локального движка на конкретной модели ТВ требует проверки.
- На компьютере для сборки: Node.js 22.12+, npm, GNU tar, OpenSSH. Перед разработкой или сборкой выполните `npm ci`.

## Разработка

На компьютере нужен Node.js 22.12+. Для просмотра UI без телевизора, TorrServer, Filmix и доступа в интернет:

```sh
npm ci
npm run dev
# http://127.0.0.1:5173/
```

`npm run dev:mock` — та же команда. Vite обслуживает приложение и локальное mock API в одном процессе, обновляет Solid-компоненты и стили при изменениях; изменение ES5-оболочки перезагружает страницу. Для другого порта: `npm run dev -- --port 5174`.

Доступны главная с постерами, каталог с фильтрами и пагинацией, описания, поиск, раздачи, файлы, Filmix, настройки и история. Вместо фильмов плеер воспроизводит локальный тестовый ролик с поддержкой Range-запросов, паузы, перемотки и переключения серий. Демо-настройки хранятся в памяти сервера до перезапуска, история — в `localStorage` браузера. Настоящие конфигурация и аккаунты не используются.

Сценарии переключаются адресом страницы:

- `http://127.0.0.1:5173/` — обычные данные;
- `http://127.0.0.1:5173/?mock=empty` — пустые результаты;
- `http://127.0.0.1:5173/?mock=error` — ошибки источников;
- `http://127.0.0.1:5173/?mock=slow` — задержка API 1,8 секунды.

Управление с компьютера: мышь, стрелки, Enter, Escape вместо BACK. Моки и тестовый ролик находятся в `dev/` и в IPK не попадают.

Для работы с настоящим Node-помощником и внешними сервисами:

```sh
TORRSERVER_URL=http://192.168.1.100:8090 npm start
# http://127.0.0.1:32190
```

Проверки и сборка:

```sh
npm run check
npm test
npx playwright install chromium # один раз для браузерных тестов
npm run test:ui
npm run build
```

`npm start` сначала собирает интерфейс. Для этого режима после изменения `src/` повторите `npm run build:ui` и обновите страницу; `npm run build` собирает интерфейс и IPK. Vite собирает JS и CSS под Chromium 68. Сгенерированные `app/catalog.js` и `app/catalog.css` исключены из Git. На ТВ уже находится готовый бандл: npm, TypeScript и зависимости из `node_modules` там не нужны.

Для постоянных настроек скопируйте `config.example.json` в `config.json` или используйте экран «Настройки». Выберите локальный режим или установите адрес внешнего сервера. `config.json` исключён из Git. Переменные `PORT`, `HOST`, `TW_CONFIG` переопределяют порт/интерфейс/путь конфигурации. На телевизоре помощник слушает только `127.0.0.1:32190`; не открывайте его в интернет.

## Установка на телевизор

```sh
./scripts/install-tv.sh root@TV_IP http://TORRSERVER_IP:8090
```

SSH/SCP спросит пароль телевизора. Скрипт не сохраняет его. Он собирает IPK, копирует его в `/tmp`, вызывает штатный webOS appInstallService, устанавливает автозапуск помощника через webOSbrew и запускает приложение. ID приложения: `org.torrenter.watcher`; название ярлыка: **VolKino**.

IPK: `dist/volkino_0.8.1_all.ipk`. Простая установка IPK через Dev Manager без root-скрипта недостаточна: нужен локальный Node-помощник. Системные разделы прошивки не изменяются. Повторная установка обновляет приложение, сохраняя настройки и историю.

На ТВ:

- приложение: `/media/developer/apps/usr/palm/applications/org.torrenter.watcher/`;
- конфигурация: `/var/lib/torrenter-watcher/config.json` (права 600, каталог 700);
- журнал/ PID помощника: `/var/lib/torrenter-watcher/helper.log`, `helper.pid`;
- автозапуск: `/var/lib/webosbrew/init.d/65-torrenter-watcher`;
- перезапуск: `sh /var/lib/webosbrew/init.d/65-torrenter-watcher restart`.

Для удаления сначала остановите PID помощника (проверьте `cmdline`), удалите его init.d-файл и удалите приложение обычным способом на ТВ. Конфигурацию/историю можно оставить для последующей установки. Root и webOSbrew остаются как были.

## Как пользоваться

1. В настройках выберите «На этом устройстве» и нажмите «Установить и запустить». Дождитесь статуса «Работает» — адрес вручную вводить не нужно. Для внешнего сервера выберите соответствующий режим, укажите адрес и учётные данные, сохраните настройки.
2. По умолчанию поиск идёт через VilkaDB — тот же портал, что в ForkPlayer.
3. Введите название, нажмите «Найти», выберите раздачу. Появятся видеофайлы; откройте нужный.
4. OK — пауза/продолжение, ←/→ — ±30 секунд, клик по полосе — переход в выбранное место, ↓ — открыть горизонтальный список видео в той же папке, ←/→ в этом списке — выбрать серию, OK — переключить с продолжением сохранённой позиции; ↑/BACK — закрыть список, ↑ вне списка — скрыть панель, жёлтая кнопка — смена аудиодорожки (если API плеера её предоставляет), BACK — к списку файлов. Системная громкость остаётся на кнопках громкости.
5. «История» хранит последние 100 открытых видео и позиции на этом ТВ; повторное открытие поднимает запись наверх, самая старая удаляется при превышении лимита; «На сервере» показывает список выбранного TorrServer.

Источники можно переключать: VilkaDB, Rutor, Torznab, Jacred. Rutor включается кнопкой в настройках, его первый индекс загружается несколько минут. Для Torznab настройте индексаторы на стороне TorrServer. Для Jacred нужен доступный адрес агрегатора, при необходимости API-ключ.

## Локальный TorrServer

«Установить и запустить» загружает официальный бинарный файл MatriX.147.2 для архитектуры устройства, проверяет закреплённую SHA-256 и автоматически выбирает локальный режим. Загрузка идёт в фоне, статус и ошибки видны в настройках. Повторное нажатие использует установленный файл. При недоступности GitHub можно повторить установку позже.

HTTP API TorrServer слушает только `127.0.0.1:32191`; соединения с участниками раздач используют сетевые интерфейсы устройства. Для разработки порт можно изменить через `TW_TORRSERVER_PORT`. Настройки внешнего сервера сохраняются отдельно, его логин и пароль локальному процессу не передаются.

Выбранный локальный режим автоматически запускается вместе с Node-помощником при перезагрузке телевизора. Закрытие окна приложения не останавливает сервер. «Остановить» завершает процесс и переключает режим на внешний, отключая локальный автозапуск. Сохранение внешнего режима также останавливает локальный процесс. Остановка помощника завершает дочерний TorrServer.

На ТВ бинарный файл, база и настройки хранятся в `/var/lib/torrenter-watcher/torrserver/`, журнал — `torrserver/torrserver.log` (ротация при запуске после 1 МиБ). При разработке это каталог `torrserver/` рядом с файлом конфигурации. Установка обновления приложения сохраняет эти данные. Для полного удаления после остановки помощника можно удалить этот каталог. Бинарник не входит в IPK: первая установка требует интернета и места для загрузки.

На Linux x86_64 проверены загрузка с SHA-256, запуск настоящего TorrServer, ограничения кэша, остановка и повторный запуск. Проверка потокового просмотра на самом webOS с этой версией ещё нужна; тяжёлые раздачи могут превышать возможности памяти и процессора ТВ.

## Архитектура и ограничения

- `src/app/`: общий UI, корневые провайдеры и стили (`styles/index.css`).
- `src/screens/`: папки экранов. Умный компонент каталога: `catalog/model/index.ts` экспортирует `CatalogVM extends ViewModelBase`, `catalog/ui/index.tsx` — `Catalog = withViewModel(CatalogVM, ...)`. Связь с Solid — через `mobx-view-model-solid` и `mobx-solid`.
- `src/globals/`: контейнер `Globals` с общими сервисами, состоянием экранов и `stores.viewModels`. Фильтры, часовой кэш страницы, выбранная карточка и прокрутка сохраняются между открытиями экрана; запоздалые ответы игнорируются, реакции очищаются при уходе.
- `src/main.tsx`: полифиллы и подключение к существующей оболочке. `vite.config.mts` собирает локальный IIFE-бандл и CSS для Chromium 68 с полифиллами `globalThis`, `structuredClone`, `queueMicrotask`, `Object.hasOwn`.
- `app/`: загрузчик webOS и готовая сборка Vite. Все экраны находятся в `src/screens/`, имеют собственные ViewModel и используют `Globals` через общую базовую `VM`. Нативный `<video>` использует возможности webOS. CDN и загрузки скриптов из сети нет.
- `server/`: локальный Node 8-совместимый HTTP-помощник: поиск, управление локальным TorrServer, CORS/Auth для внешнего сервера, потоковая передача Range-запросов без транскодирования.
- В локальном режиме скачивания и пиры работают на ТВ: кэш видео в памяти 32 МиБ, до 20 соединений, сохранение видео на диск выключено. Расход памяти всего процесса выше размера кэша; GOMEMLIMIT=96MiB — мягкий ориентир Go, а не жёсткий лимит. Внешний режим переносит эту нагрузку на отдельную машину. Помощник передаёт HTTP-поток с противодавлением; его V8 heap ограничен 64 МБ.
- Нет сидов — нет гарантии запуска. Счётчик сидов каталога может отставать от реального состояния. Ошибки и ожидание отображаются, запросы метаданных ограничены по времени.
- Поддержка кодеков зависит от ТВ. TorrServer передаёт оригинальный файл и не исправляет неподдерживаемые звук/видео.
- VilkaDB — внешний HTTP-портал без гарантии стабильности API. HTML/JS/CSS портала не исполняются. Запрос поиска отправляется выбранному источнику, а история остаётся в `localStorage` телевизора.
- Пароль и API-ключ не возвращаются в API чтения настроек и не пишутся в браузерное хранилище. Локальные изменения защищены токеном сессии и проверкой Host. Помощник не предназначен для доступа из интернета.

Исследование протоколов и источники: [docs/research.md](docs/research.md).


## Главная и каталог (0.2.0)

При запуске открывается «Главная»: локальное «Продолжить просмотр» и подборки фильмов и сериалов. В настройках источник подборок можно выбрать отдельно от источника поиска торрентов: VilkaDB, CUB, Filmix, Cinemeta или YTS. По умолчанию используется VilkaDB. Ключ API не нужен; Filmix работает в гостевом режиме мобильного подключения или с настроенной сессией Filmix TV.

CUB предлагает русскоязычные подборки, Cinemeta — преимущественно английские. Filmix показывает последние добавления и обновления, включая обновления старых сериалов; подборки по году фильтруются среди последних добавлений. YTS содержит только фильмы, популярность определяется числом загрузок, а новые фильмы — среди последних добавлений; названия преимущественно английские. Все источники сторонние, их доступность может меняться.

В каждой подборке до 18 карточек; ряды прокручиваются горизонтально пультом и Magic Remote. Карточка показывает постер, рейтинг, год и тип. Нажатие открывает описание и автоматически ищет раздачи выбранным источником. Список появляется под постером и описанием; выбор раздачи ведёт к обычному пути через TorrServer. BACK из списка файлов возвращает к тому же фильму, выбранной раздаче и прокрутке.

Подборки каждого источника кэшируются отдельно на 3 часа, описания VilkaDB — на сутки, нормализованные данные сохраняются рядом с config.json в catalog-cache.json. При временной недоступности источника показывается сохранённая подборка. Постеры идут через локальный помощник. История портала не импортируется — ряд продолжения берётся только из локальной истории этого устройства.

Подборки новых фильмов/сериалов фильтруются по году источника; наличие карточки не гарантирует доступную торрент-раздачу. Отдельный экран «Каталог» продолжает использовать VilkaDB.


## Каталог (0.3.2)

Отдельный пункт меню «Каталог» позволяет просматривать все годы, выбирать фильмы или сериалы, жанр и минимальный рейтинг (любой, от 5/6/7/8/9). Наборы жанров соответствуют выбранному типу; при смене типа жанр сбрасывается. Доступен точный год (1900 — текущий) и сортировки «Популярное», «Новее», «По рейтингу». Источник не поддерживает сортировку всего каталога: сортировки по году и рейтингу применяются к текущей странице; одинаковые значения сохраняют исходный порядок. Нажмите «Показать», чтобы применить фильтры. Страницы содержат до 36 карточек; переходы «Следующая»/«Предыдущая» сохраняют фильтры.

На пульте стрелки перемещают фокус между полями по их расположению на экране: например, ↓ с «Тип» ведёт к «Год». OK открывает список значений; внутри списка ↑/↓ выбирают вариант, OK подтверждает, BACK отменяет. Значение закрытого поля при перемещении фокуса не меняется. Мышь открывает тот же список. OK на «Показать» применяет фильтры. Из карточки можно открыть описание и найти раздачи. BACK возвращает к выбранной карточке и той же странице каталога. Результаты фильтрации кэшируются на час в существующем ограниченном кэше метаданных. Минимальный рейтинг дополнительно проверяется после ответа источника.

## Плеер и серии (0.4.1)

Панель плеера и список серий автоматически скрываются после 5 секунд без действий во время воспроизведения. Пауза, буферизация и незавершённая перемотка оставляют панель видимой; после восстановления просмотра таймер запускается снова. Клик по полосе перемотки больше не закрепляет панель, мелкое дрожание указателя игнорируется.

Стрелка ↓ открывает горизонтальный ряд видео из той же папки раздачи, выделяя текущую серию. ←/→ перемещают выбор, OK переключает серию и сохраняет позицию предыдущей. Выбор текущей серии закрывает список. ↑ или BACK закрывают список; следующий BACK выходит из плеера. Для перемотки при открытом списке доступны кнопки перемотки пульта или клик по полосе.

Внизу карточек файлов и серий показана тонкая линия: пустая — файл ещё не смотрели, частично заполненная — позиция просмотра, полная — просмотрено не менее 95% или достигнут конец видео. Прогресс берётся из локальной истории этого ТВ, которая хранит последние 100 файлов.

## Последние добавления

Страница «Последние добавления» в боковом меню показывает только **Filmix**: фильмы и сериалы обычным списком, с типом, годом и датой публикации/обновления. Новые серии и озвучки могут поднять старый сериал наверх; последняя серия показывается, если API её сообщает. Нажатие сразу открывает файлы Filmix. Есть пагинация, обновление списка и восстановление выбранной строки/прокрутки после возврата.

VilkaDB на этой странице не отображается, поскольку проверенный API не сообщает дату добавления. Его обычный каталог доступен на странице «Каталог».

Данные кэшируются на 5 минут; «Обновить список» обходит наш кэш. При недоступности Filmix может отображаться сохранённый список с предупреждением. Mock-режим поддерживает ленту Filmix и сценарии `?mock=empty`, `?mock=error`.

## Автофикс звука

В «Настройки» → «Звук» → «Автофикс звука» доступны «Выключен» (по умолчанию), «Умеренный» и «Ночной». Сохраните настройки и откройте видео заново. «Ночной» сильнее сглаживает разницу между тихими сценами и громкими эффектами. Режим сохраняется в конфигурации помощника, а в локальной dev-среде — в памяти mock-сервера.

Обработка использует Web Audio: перевод в стерео, компрессор динамического диапазона, компенсация тихих участков и ограничение пиков. Это не выделение речи: фоновый шум тоже может стать слышнее. Многоканальный вывод и исходный passthrough для этого режима не сохраняются; «Выключен» использует оригинальный нативный звуковой тракт.

В панели плеера «Звук и изображение» можно переключить автофикс для текущего видео. Настройка применяется сразу, сохраняет позицию и состояние паузы и не меняет общий режим; при открытии следующего видео снова используется общая настройка. При ошибке запуска обработки или отсутствии сигнала в первые 12 секунд активного воспроизведения приложение возвращается к оригинальному звуку, восстанавливая видео и позицию. Полностью тихое начало фильма тоже может вызвать такое отключение для текущего видео.

В современном Chromium проверены измеряемое сжатие динамики, воспроизведение, переключение серий, сохранение настройки и восстановление после сбоя. Работа с нативным декодером конкретного LG/webOS пока требует проверки на телевизоре. Без Web Audio доступны только оригинальный звук и режим «Выключен».

По умолчанию Filmix использует «Мобильный API». Сохранённый выбор веб-подключения остаётся без изменений.

## Filmix TV — веб-клиент Media Station X

В настройках Filmix выберите «Filmix TV — как в Media Station X» и войдите по логину/e-mail и паролю. Пароль передаётся по HTTPS только при входе и не сохраняется. Ключ устройства и access/refresh-токены хранятся в закрытом конфигурационном файле помощника; в браузерный API настроек они не попадают. Если Filmix сообщает о лимите устройств, освободите слот в личном кабинете.

Веб-режим использует `https://api.filmix.tv/api-fx` и авторизованную страницу `https://filmix.tv/watch?id=...`. Данные страницы разбираются как JSON без исполнения скриптов. Заголовки запросов соответствуют веб-протоколу (`Origin`, `Referer`, `hash`, Bearer); это не меняет внешний IP подключения и не гарантирует неотличимость клиента.

Каталог, поиск, карточки и доступное качество берутся из веб-сессии. Сессия обновляется через refresh-токен; автоматического отката к мобильному API нет. Локальный прокси поддерживает MP4 и HLS, включая вложенные плейлисты, сегменты и URI ключей. Качество ограничивается правами аккаунта. Неиспользуемую сессию можно отключить в настройках.

## Filmix: прежний мобильный API (0.5.0)

На странице фильма/сериала появилась кнопка «Смотреть через Filmix». В обычном поиске есть отдельная кнопка «Filmix». Введите название, выберите нужное совпадение по названию и году, затем озвучку, сезон и качество. Видео открывается в нашем плеере; TorrServer для этого не нужен. Начальный экран теперь доступен и без настроенного TorrServer.

Для подключения аккаунта откройте «Настройки» → «Filmix — онлайн-просмотр»:

1. Нажмите «Получить код Filmix».
2. На телефоне или компьютере войдите в свой аккаунт Filmix и введите код на странице `/consoles` указанного сайта.
3. Вернитесь в приложение и нажмите «Я ввёл код».
4. «Проверить Filmix» показывает аккаунт и доступное качество. «Отключить Filmix» удаляет сохранённый токен из приложения; привязкой устройства на сайте управляет сам пользователь.

Можно также ввести существующий токен в настройках. Пароль аккаунта приложению не нужен. Код ожидает активации до 15 минут; после перезапуска помощника нужно запросить новый код. Проверка активации выполняется кнопкой, без фонового опроса сайта.

Адаптер ограничивает качество: гость — до 480p, аккаунт без PRO — до 720p, PRO — до 1080p, PRO+ — до 2160p. Фактические варианты зависят от доступных видео, профиля Filmix и поддерживаемых ТВ кодеков. Если нужного качества нет у серии, выбирается ближайшее доступное ниже заданного предела. Смена озвучки сохраняет общий прогресс этой серии. Переключение по ↓ и полоски просмотра работают так же, как для торрентов.

Токен и постоянный ID устройства хранятся только в конфигурации Node-помощника с правами 600, не возвращаются в API чтения настроек и не сохраняются в `localStorage`. История хранит ID фильма и серии, озвучку, сезон и позицию; при продолжении запрашивается новая ссылка на поток. Медиассылки и токен не записываются в историю. MP4 передаётся через локальный потоковый прокси с Range/HEAD и противодавлением, без записи видео на диск и без транскодирования. Прокси принимает только созданные помощником временные идентификаторы потоков, проверяет публичные адреса CDN и перенаправлений.

`filmixApiUrl` по умолчанию — `http://filmixapp.cyou/api/v2`, `filmixSiteUrl` — `https://filmix.my`. Адреса можно менять в настройках при смене доменов Filmix. API по умолчанию использует HTTP: токен устройства передаётся ему без TLS. Если у Filmix доступен рабочий HTTPS API, укажите его; проверка сертификатов не отключается. Не путайте адрес API с адресом сайта для ввода кода.

Это интеграция с мобильным API v2, без исполнения скриптов сайта. Стабильность стороннего API и доступность конкретных видео не гарантируются; HLS и веб-плеер сайта в этой версии не используются. Живая проверка: Big Buck Bunny (Filmix ID 7031), поиск, получение озвучек, Range/206, воспроизведение и продолжение из истории в браузере; отдельно подтверждён поток через Node 8.17.0. Получение настоящего кода устройства проверено, завершение привязки аккаунта проверяется mock-тестом — реальный аккаунт и воспроизведение на webOS ещё требуют проверки.

Источники формата протокола: [Lampa Filmix adapter](https://github.com/yumata/lampa-source/blob/master/plugins/online/filmix.js), [Lampa device activation](https://github.com/yumata/lampa-source/blob/master/plugins/online/online.js), [go-filmix API models](https://github.com/n0madic/go-filmix/tree/main/models). Эти проекты используются как справочные материалы; дополнительных runtime-зависимостей нет.
